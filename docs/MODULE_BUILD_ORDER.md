## Resolving the Shopify Plugin conflict

`MODULE_DEPENDENCY_GRAPH.md` gates Shopify Plugin at Stage 6 ("if not already shipped"); `FIVE_YEAR_EXECUTION_PLAN.md` sequences it at position #12, inside Stage 4–5. Both are correct once read as answering different questions: **Stage 4–5 is when Shopify Plugin can start** (its dependencies — `visibility-layer`, `telemetry` — are stable by Stage 4, and WordPress Plugin should ship first per the roadmap's "WordPress-first" decision to prove the install-driven attach-rate thesis on the larger CMS segment before repeating it on a stricter, smaller one). **Stage 6 is the latest it's required by** (the dependency graph's exit-criteria table, i.e. the deadline, not the earliest start). This document adopts that reading: recommended start Stage 4–5, hard requirement Stage 6. No numeric reordering was needed — the two source docs are compatible once "recommended start" and "required by" are treated as different columns, which is what this table does below.

## How to use this document

Before starting item N, confirm every dependency listed for it is at "v1 shipped" status for the targeted stage — a scaffold satisfies nothing about the dependency graph (per `MODULE_DEPENDENCY_GRAPH.md`'s own framing). The "Customer demand trigger" column is the signal to watch for, not a guarantee — cross-reference `docs/DO_NOT_BUILD_YET.md` for what stays postponed until that signal actually appears.
